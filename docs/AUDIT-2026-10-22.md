## High-priority security findings

### S1 — Profile role and privilege fields may be user-editable through the current table grant/policy combination

Evidence: live grants confirm `authenticated` has table-level INSERT/UPDATE/DELETE on `profiles`, and the row policy allows self-update. A deployed `guard_profile_sensitive_fields` trigger also rejects changes to `role`, `premium`, `verified`, identity, email, and derived counters for non-admin clients. Thus a direct privilege escalation was not demonstrated; broad table grants remain an avoidable attack surface and should be narrowed as defense in depth. The branch migration grants UPDATE only on ordinary profile fields. No exploit test or migration application has been performed.
**Next:** validate the column-grant migration against signup, profile edits, and admin flows before deployment.

### S2 — Merchant self-approval / plan changes may be possible

Evidence: live grants confirm broad INSERT/UPDATE/DELETE on `merchants`. A deployed `guard_merchant_sensitive_fields` trigger already rejects owner-supplied approval, verification, plan, rating, commission, and derived-count changes; another trigger guards owner-controlled fields. The branch migration adds least-privilege column grants and a stricter insert policy as defense in depth. No exploit was tested and the proposed migration is not deployed.
**Next:** validate the storefront-only INSERT payload and merchant editing/admin approval flows against the migration.

### S3 — Supabase Security Advisor reports exposed SECURITY DEFINER RPCs

Live advisor result observed 2026-10-22:
- Four functions are executable by `anon`: `battle_result(uuid)`, `is_admin()`, `is_merchant_owner(uuid)`, and `similar_looks(uuid, integer)`.
- Eleven SECURITY DEFINER functions are executable by `authenticated`, including `admin_overview()`, `merchant_stats(uuid)`, and mutation RPCs.
- The advisor also reports leaked-password protection disabled.
These are warnings requiring function-by-function review, not proof that every listed function is exploitable. The reviewed public RPCs `is_admin()` and `is_merchant_owner(uuid)` return only boolean values tied to `auth.uid()`; `battle_result(uuid)` returns public battle/look content; mutation RPCs such as `set_like`, `toggle_follow`, `toggle_save`, and `vote_in_battle` compare supplied user IDs with `auth.uid()`; `merchant_stats(uuid)` checks owner/admin access; and `admin_overview()` gates its output on `is_admin()`. One actionable hardening gap is that `similar_looks(uuid, integer)` accepts an unbounded client-supplied row limit. Branch migration `0006_bound_similar_looks_rpc.sql` caps this to 1–12 results. These branch changes and test assertions have not been applied to production. Enable leaked-password protection after confirming intended Auth policy.
Remediation: https://supabase.com/docs/guides/database/database-linter?lint=0028_anon_security_definer_function_executable

### S4 — Public profile read policy exposes profile rows

Evidence: live grants confirmed `anon` has SELECT on `profiles`, and column-level privileges include `profiles.email`; `profiles_select` is `USING (true)`. This confirms the email field is exposed at the database privilege/policy layer, although no external data extraction was attempted. The branch now contains migration `0005_public_profile_email_isolation.sql`, a safe `public_profiles` view excluding email/role/premium, and client changes that use the view for community discovery. The migration is not applied to production and compatibility tests have not run.
**Next:** validate public profile discovery, self-profile reads, and admin user listing in an isolated database.

## Reliability and product gaps

- The Edge Function uses a server-side service-role client only after validating the user's bearer token, which is a positive control. It validates several inputs and limits budget, palette, and note lengths.
- The Edge Function's CORS policy allows all origins. This is not authentication by itself, but should be narrowed if the product's supported origins are known.
- Image styling is explicitly unsupported in the checked-in AI function. Keep UI copy honest and do not claim end-to-end image recommendations until an uploaded, server-accessible image flow is implemented and tested.
- The AI function hardcodes OpenRouter's `openrouter/free` route while repository documentation describes configurable OpenAI/Anthropic providers. Reconcile documentation with runtime implementation before making provider-switchability claims.
- Supabase performance advisor reports 13 foreign keys without covering indexes and 24 RLS policies with auth-function initplan warnings. Prioritize indexes after query-path review; optimize RLS expressions with `(select auth.uid())` where correct.
- The connected Supabase project is active and has ATHR-shaped tables with RLS enabled. A healthy project status is not proof that all migrations, Edge Functions, secrets, and mobile environment settings match the current repository.
- No production migrations, deployments, payment setup, or account settings were changed during this audit.
